🐬 Manual Completo de SQL (Basado en MySQL)

1. Introducción a Bases de Datos y SQL

  • SQL (Structured Query Language): Lenguaje utilizado para crear, recuperar, actualizar y borrar datos (operaciones CRUD) en una base de datos.
  • Bases de Datos Relacionales: Organizan los datos en tablas con filas y columnas. Las tablas se vinculan entre sí utilizando llaves (keys) y operan bajo lenguaje SQL.
  • Bases de Datos No Relacionales (NoSQL): Organizan la información en formatos alternativos como documentos JSON, pares clave-valor o estructuras de grafos.
  • DBMS (Database Management System): Software gestor que proporciona el espacio de trabajo para administrar las bases de datos (Ej: MySQL, PostgreSQL, Oracle, SQL Server).

Configuración de Conexión Estándar

Para establecer conexión con el servidor de MySQL local a través de MySQL Workbench se requiere:

  • Método: Standard TCP/IP
  • Hostname: 127.0.0.1 (Localhost)
  • Puerto: 3306

2. Gestión de Bases de Datos (Esquemas)

Las palabras clave en SQL no distinguen entre mayúsculas y minúsculas. Sin embargo, se aconseja estructurarlas en mayúsculas para aumentar la legibilidad del código. Cada instrucción debe cerrarse con un punto y coma (;).

-- Crear una nueva base de datos
CREATE DATABASE mydb;

-- Seleccionar el esquema para empezar a trabajar
USE mydb;

-- Eliminar de forma definitiva la base de datos
DROP DATABASE mydb;

-- Alterar la base de datos (Ej: Modo lectura para proteger datos)
ALTER DATABASE mydb READ ONLY = 1; -- 1 activa lectura, 0 la desactiva

3. Operaciones Básicas con Tablas (DDL)

Las tablas representan las estructuras encargadas de definir las columnas junto con sus respectivos tipos de datos permitidos.

Tipos de Datos Comunes

  • INT: Números enteros sin decimales.
  • VARCHAR(X): Almacena cadenas de texto con un límite máximo ajustable de X caracteres.
  • DECIMAL(M, D): Números de precisión exacta. Donde M es la cantidad total de dígitos y D la cantidad de decimales reservados (Ej: DECIMAL(5,2) almacena valores hasta el 999.99).
  • DATE: Almacena fechas bajo el estándar estructural AAAA-MM-DD.
  • DATETIME: Registra simultáneamente tanto la fecha como la hora exacta de un suceso.

Comandos de Estructura

-- Crear una tabla inicial
CREATE TABLE empleados (
    empleado_id INT,
    nombre VARCHAR(50),
    apellido VARCHAR(50),
    pago_hora DECIMAL(5,2),
    fecha_contratacion DATE
);

-- Renombrar una tabla dentro del esquema
RENAME TABLE empleados TO trabajadores;

-- Eliminar la tabla por completo
DROP TABLE empleados;

Alterar Tablas (ALTER TABLE)

-- Incorporar una nueva columna
ALTER TABLE empleados ADD telefono VARCHAR(15);

-- Renombrar una columna existente
ALTER TABLE empleados RENAME COLUMN telefono TO email;

-- Modificar el tipo de dato o longitud de una columna
ALTER TABLE empleados MODIFY COLUMN email VARCHAR(100);

-- Reposicionar una columna en la tabla
ALTER TABLE empleados MODIFY COLUMN email VARCHAR(100) AFTER apellido;

-- Remover una columna
ALTER TABLE empleados DROP COLUMN email;

4. Manipulación de Datos (DML) y Consultas

Insertar Datos (INSERT INTO)

-- Insertar un registro completo respetando el orden de columnas
INSERT INTO empleados VALUES (1, 'Eugene', 'Cangrejo', 25.50, '2023-01-02');

-- Inserción masiva de múltiples registros simultáneos
INSERT INTO empleados VALUES 
(2, 'Calamardo', 'Tentáculos', 15.00, '2023-01-03'),
(3, 'Bob', 'Esponja', 12.50, '2023-01-04');

-- Insertar omitiendo ciertas columnas (las omitidas se guardarán como NULL)
INSERT INTO empleados (empleado_id, nombre, apellido) VALUES (6, 'Sheldon', 'Plankton');

Seleccionar y Filtrar (SELECT + WHERE)

El uso del operador asterisco (*) indica al motor de base de datos la selección de todas las columnas disponibles de una tabla.

-- Selección selectiva de columnas
SELECT nombre, apellido FROM empleados;

-- Filtrado preciso con la cláusula WHERE
SELECT * FROM empleados WHERE empleado_id = 1;
SELECT * FROM empleados WHERE pago_hora >= 15.00;

-- Validación correcta de campos vacíos (Se utiliza "IS NULL" / "IS NOT NULL")
SELECT * FROM empleados WHERE fecha_contratacion IS NULL;
SELECT * FROM empleados WHERE fecha_contratacion IS NOT NULL;

⚠️ ADVERTENCIA CRÍTICA: Si se ejecuta una sentencia UPDATE o DELETE omitiendo por descuido la cláusula WHERE, el cambio afectará de forma irreversible a todos los registros de la tabla.

-- Actualización de datos puntuales
UPDATE empleados 
SET pago_hora = 10.25, fecha_contratacion = '2023-01-07' 
WHERE empleado_id = 6;

-- Eliminación controlada de un registro
DELETE FROM empleados WHERE empleado_id = 6;

5. Transacciones (COMMIT y ROLLBACK)

Por defecto, MySQL opera en modo autocommit, lo que guarda inmediatamente cualquier instrucción ejecutada. Desactivar esta opción permite manipular bases de datos de forma segura mediante la creación de puntos de restauración manuales.

-- Apagar el guardado inmediato automático
SET autocommit = OFF;

-- Confirmar de forma manual y crear un punto seguro de restauración
COMMIT;

-- Caso de error: Borrado accidental sin filtrar
DELETE FROM empleados;

-- Deshacer la última operación fallida regresando al estado del último COMMIT
ROLLBACK;

6. Restricciones (Constraints)

Las restricciones se asocian de manera directa a columnas específicas para validar o limitar el tipo de datos aceptados dentro del sistema.

  • UNIQUE: Garantiza que ningún valor de la columna se repita en la tabla.
  • NOT NULL: Prohíbe la inserción de campos vacíos (NULL).
  • CHECK: Condiciona la entrada evaluando una regla lógica (Ej: rangos numéricos).
  • DEFAULT: Inyecta de forma automatizada un valor predeterminado si el usuario omite el campo.
  • PRIMARY KEY: Identificador único de cada fila de la tabla. Es la unión estricta de las reglas UNIQUE y NOT NULL. Sólo puede existir una por tabla.
  • AUTO_INCREMENT: Instruye a campos clave enteros para autogenerarse incrementando su valor secuencialmente en 1.
-- Creación de tabla aplicando restricciones integradas
CREATE TABLE productos (
    producto_id INT PRIMARY KEY AUTO_INCREMENT,
    nombre_producto VARCHAR(25) UNIQUE NOT NULL,
    precio DECIMAL(4,2) DEFAULT 0.00,
    CONSTRAINT chk_precio CHECK (precio >= 0.00)
);

-- Inyectar restricciones en estructuras ya preexistentes
ALTER TABLE productos ADD CONSTRAINT nombre_unico UNIQUE (nombre_producto);

7. Llaves Foráneas y Uniones (FOREIGN KEY y JOINS)

Llave Foránea (FOREIGN KEY)

Es una columna que sirve de puente de comunicación vinculando de forma directa la PRIMARY KEY perteneciente a una tabla externa. Resguarda la integridad referencial, bloqueando intentos de borrado sobre un elemento padre si este cuenta aún con elementos hijos subordinados.

CREATE TABLE transacciones (
    transaccion_id INT PRIMARY KEY AUTO_INCREMENT,
    monto DECIMAL(5,2),
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES clientes(customer_id)
);

Tipos de Joins (Combinación de tablas)

  • INNER JOIN: Reúne y entrega únicamente las filas cuyas llaves tengan una correspondencia exacta en ambas tablas.
  • LEFT JOIN: Entrega el universo completo de la tabla izquierda, junto a los datos emparejados de la derecha. Si no hay coincidencia, rellena con campos vacíos (NULL).
  • RIGHT JOIN: Entrega el universo completo de la tabla derecha, trayendo los emparejamientos encontrados de la tabla izquierda.

Cláusulas de Comportamiento ON DELETE

Determinan la acción automática a tomar en la fila hija tras remover la fila padre de la base de datos:

  • ON DELETE SET NULL: Resetea el campo de la llave foránea secundaria del hijo a NULL.
  • ON DELETE CASCADE: Ejecuta un borrado en cadena, destruyendo al hijo en consecuencia.

8. Funciones Agregadas y Operadores Lógicos

Funciones de Agregación

  • COUNT(): Efectúa el conteo total de filas coincidentes.
  • MAX() / MIN(): Extraen respectivamente el valor numérico más alto o bajo detectado.
  • AVG(): Ejecuta el cálculo promedio aritmético sobre el grupo de datos.
  • SUM(): Totaliza mediante la adición de los valores acumulados.
  • CONCAT(): Enlaza textos dispersos en múltiples campos en una única cadena uniforme.
  • AS: Crea alias representativos modificando el nombre visual de campos temporalmente.

Operadores Lógicos y Comodines (Wildcards)

  • AND, OR, NOT: Permiten hilar y condicionar búsquedas mediante álgebra lógica estructurada.
  • BETWEEN X AND Y: Acota resultados validando rangos de forma estrictamente inclusiva.
  • IN (): Simplifica la búsqueda comprobando si un valor está incluido en un listado predefinido.
  • LIKE: Ejecuta búsquedas avanzadas de texto mediante patrones asistidos por comodines:
    • %: Reemplaza dinámicamente un número indefinido de caracteres aleatorios.
    • _: Sustituye con exactitud un único carácter aislado por posición.

9. Ordenar, Limitar y Agrupar Datos

ORDER BY y LIMIT

  • ORDER BY columna ASC/DESC: Modifica la disposición de filas presentándolas de forma ascendente o descendente.
  • LIMIT X: Impone un tope para procesar únicamente un volumen X máximo de filas.

GROUP BY, HAVING y ROLLUP

  • GROUP BY: Compacta filas duplicadas compartidas bajo un criterio agrupador, ideal para operar funciones agregadas.
  • HAVING: Identico al operador WHERE, pero actúa aplicando restricciones exclusivamente sobre los datos consolidados tras la ejecución del GROUP BY.
  • WITH ROLLUP: Agrega una fila de superagregación al final mostrando el cálculo del gran total acumulativo del grupo.

10. Operaciones Avanzadas

UNION

Une la salida resultante de varias peticiones SELECT. Exige como prerrequisito que las consultas cuenten exactamente con el mismo número de columnas asignadas bajo el mismo orden tipificado.

  • UNION: Purga y descarta filas repetidas del set definitivo.
  • UNION ALL: Junta las tablas anexando todo, sin discriminar registros repetidos.

Subconsultas (Subqueries)

Incrustación de una petición SQL completa alojada internamente en otra mayor (delimitada por paréntesis). Su ejecución es prioritaria, entregando el resultado a la consulta contenedora externa para su resolución final.

Vistas (VIEWS)

Tablas virtuales dinámicas de carácter lógico generadas a partir del mapeo de consultas reales. No replican la información, manteniendo sincronización automática ante alteraciones del origen real de los datos.

Índices (INDEX)

Estructuras optimizadas diseñadas para agilizar la localización de información en columnas de alta demanda.

  • Ventaja: Incrementa la velocidad en lecturas y búsquedas de datos.
  • Desventaja: Reduce marginalmente la velocidad operativa de escrituras (INSERT, UPDATE) por mantenimiento estructural.

11. Procedimientos Almacenados y Triggers

Procedimientos Almacenados (Stored Procedures)

Fragmentos de sentencias SQL compilados directamente en el servidor listos para ser invocados reiteradamente mediante un alias identificador. Maximizan el rendimiento reduciendo la transferencia de tráfico en la red. Demandan el cambio del delimitador (DELIMITER) para evitar malinterpretaciones del motor al procesar el punto y coma nativo interno.

DELIMITER $$
CREATE PROCEDURE EncontrarCliente(IN cliente_id INT)
BEGIN
    SELECT * FROM clientes WHERE customer_id = cliente_id;
END $$
DELIMITER ;

-- Invocación
CALL EncontrarCliente(3);

Triggers (Disparadores)

Rutinas de código automatizadas programadas para reaccionar inmediatamente ante la llegada de un evento operativo (INSERT, UPDATE, o DELETE) sobre tablas vigiladas. Utilizan variables contextuales de captura de estado: NEW (atrapa valores entrantes) y OLD (atrapa valores preexistentes modificados o removidos).

CREATE TRIGGER antes_actualizar_pago
BEFORE UPDATE ON empleados
FOR EACH ROW
BEGIN
    SET NEW.salario = NEW.pago_hora * 2080;
END;
